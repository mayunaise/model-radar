# GLM Radar V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish the first production-ready version of GLM Radar: a GitHub Pages portal that summarizes GLM-related changes across four open-source frameworks and exposes a filterable capability matrix.

**Architecture:** Astro renders a fully static site from versioned JSON shards. A scheduled GitHub Actions pipeline collects GitHub issues and pull requests, filters GLM-related changes, asks one tightly constrained OpenAI model for structured summaries, writes immutable data shards to a `data` branch, and dispatches a Pages rebuild. The public site has no database, server, admin endpoint, or browser-side secret.

**Tech Stack:** Astro 7, TypeScript, Zod, Vitest, `@octokit/rest`, OpenAI JavaScript SDK, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-08-20-glm-radar-v1-design.md`

## Global Constraints

- The initial monitor list is exactly `hiyouga/LlamaFactory`, `Ascend/MindSpeed-LLM`, `volcengine/verl`, and `vllm-project/vllm`; additions happen through reviewed config changes.
- The browser never receives `OPENAI_API_KEY`, `GITHUB_TOKEN`, or any administrative credential.
- OpenAI calls use only `gpt-5.6-luna`, `reasoning.effort: "none"`, no tools, strict structured output, one retry, and no fallback model.
- The collector refuses work above 120 candidate items per day or above the configured USD safety budget. Deferred items are retained as backlog candidates.
- User-derived text is rendered as text, never with `set:html` or `innerHTML`.
- All workflow actions are pinned to immutable commit SHAs.
- Each task follows red-green-refactor: write a failing test, run it, implement the minimum, run it again, then commit.

## Acceptance Gate

- [ ] The production build succeeds using fixture data and using a copied data-branch tree.
- [ ] All public routes are navigable without JavaScript; JavaScript only enhances filters.
- [ ] Every displayed issue/PR can be traced to an upstream URL, and every capability claim has evidence or is explicitly `待核实`.
- [ ] The sync pipeline is idempotent and stops safely on GitHub rate limits, OpenAI schema failure, item cap, or budget cap.
- [ ] No browser bundle, build artifact, log fixture, or workflow artifact contains a credential.
- [ ] GitHub identity and Organization controls replace any site-level administrator password.
- [ ] The repository is ready for the user to configure Organization rules, add the OpenAI secret, create the `data` branch, and enable GitHub Pages.
